# Phase 01 Plan 04: Ship-ready — install docs, an automated release gate, and the user-gated go install check

## Phase Goal

**As a** prv user who watches my own GitHub pull requests, **I want to** run `prv` and see, from live GitHub data, every PR I authored or am assigned to with its state, review status and CI badge, **so that** I can tell which are approved, blocked or failing CI without opening a browser.

<objective>
Close CONF-02 and lock AUTH-03 for the phase. Task 1 writes a README a new user can install and authenticate from, then runs an automated release gate: formatting, vet, race tests, the Go 1.26 floor, a local go install into an empty GOBIN with CGO_ENABLED=0, --version, the no-token exit, and token and output hygiene. Task 2 is the user-gated checkpoint (user decision 3): the user pushes (and optionally tags) when ready, then confirms that `go install github.com/sbartram/prv/cmd/prv@latest` works. Nothing is pushed automatically.

Purpose: success criterion 5 (installable binary with a version) and the phase-level token-hygiene gate.
Output: `README.md`, `.gitignore`, a recorded readiness run, the user's go install confirmation.
</objective>

## Flagged assumptions (carried, not silently dropped)

- CONF-02 (edge unclassified by the probe) and RESEARCH A8: `go install ...@latest` can only be proven after the user pushes. Untagged, `--version` prints a pseudo-version such as `v0.0.0-20261011...-abcdef123456`; with a `v0.1.0` tag it prints `v0.1.0`. Task 1 proves the install path locally; Task 2 proves it through the module proxy.
- The module proxy may cache `@latest` for a short time after a push; `GOPROXY=direct` bypasses that cache for the check.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repository → github.com (push) | Everything committed becomes public in a public repository |
| module proxy → user machine (go install) | The published module is fetched and built on the user's machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Information disclosure | repository contents before the push | high | mitigate | Release gate greps every tracked and untracked non-ignored file for token-shaped strings; fixtures are synthetic (01-01, 01-02); the push is done by the user after the gate |
| T-01-17 | Tampering | published install path | medium | mitigate | Push is user-gated by a blocking-human checkpoint; the gate checks the module path and the local go install of ./cmd/prv |
| T-01-18 | Information disclosure | README token guidance | low | mitigate | README recommends read-only scopes and states prv never stores the token; it never asks the user to put a token in a file |
| T-01-SC | Tampering | go install of the published module | low | accept | Only prv's own module and the already-audited dependencies are fetched; go.sum entries are verified against sum.golang.org by the go command; no new third-party modules in this plan |
</threat_model>
