# Phase 05 Plan 02: The add prompt never lies — the backup notice, no cancel after the save starts, and a real reason for every failed save

<objective>
Show what plan 05-01's store now reports, and make the add prompt agree with the file (D-01 scope: WR-03 UI side, WR-05, IN-02).

- Task 1 (tracer): the ui `Watchlist` interface moves to `AddRef`/`RemoveRef`; the store's `Result.StartedOver` travels through `saveCmd`/`removeCmd` into the footer as "previous list saved to watchlist.json.corrupt-XXXXXXXX" (D-04), proven end to end with a real store over a corrupt file.
- Task 2: a `saving` state separate from `checking`: esc, typing and paste are ignored once the save is dispatched, the prompt says "saving REF" with no cancel hint, the spinner keeps turning (D-05, WR-05).
- Task 3: `saveReason` maps every store error to a short fixed phrase (D-06, IN-02; ErrBusy from D-09 and VersionError from D-04 included), proven end to end with a version-2 file; the Phase 4 review dispositions are recorded.

Purpose: Phase 4 review WR-03 says the user can lose saved PRs with only an 8-second startup warning as the explanation; WR-05 says esc during the save lies; IN-02 says every failure reads the same. This plan closes all three.
Output: changed `add.go`, `remove.go`, `model.go`, tests, 4 new goldens, two end-to-end tests, updated `04-REVIEW-DISPOSITION.md`.
</objective>
