# Phase 05 Plan 01: Two panes never lose a change, and a broken or newer watchlist.json is never lost silently

## Flagged assumptions and choices (carried, not silently dropped)

- **Version 0 or no version key: refused (user-confirmed 2026-10-13, recorded under D-04 in 05-CONTEXT.md).** This was a flagged assumption; the user answered "Refuse", so it is no longer an assumption. It overrides RESEARCH Pattern 3's edge note, Pitfall 9 and Open Question 3. Any watchlist.json that decodes as a JSON object whose `version` is not 1 is a version mismatch, and AddRef and RemoveRef refuse to write: `{"version": 0}`, `{"version": null}`, a non-integer version such as `"1"` or `1.0`, and an absent key (`{}`, `{"prs": [...]}`) included. Only a non-JSON file, non-object JSON (`[]`, `"x"`, `3`, `null`) or an oversized file is unparseable and may start over. Do not copy RESEARCH Pattern 3's probe struct: it cannot tell `{}` from `[]`. Task 2 step 2 gives the classification.
- **Text for a missing version (Claude's discretion within D-04):** `VersionError{Missing: true}` reads `watchlist.json has no version number; this prv writes version 1` (key absent, null or not an integer). A declared 0 reads `watchlist.json is version 0; this prv writes version 1`.
- **A version-1 object that does not decode (planner's reading, reversible):** for example `{"version": 1, "prs": {"x": 1}}`, or an entry whose number is a string. It declares version 1, so it is not a version mismatch; prv cannot parse it as a version-1 list, so it counts as unparseable and starts over after its backup, as it does today. Neither D-04 nor the 2026-10-13 answer names this case. The user can overrule it at verification (one branch in read()).
- **Lock timeout (Claude's discretion, D-09):** 3 s total, 10 ms poll. A real hold is one fsync (milliseconds).
- **Notice shape (Claude's discretion, D-04):** new `AddRef`/`RemoveRef` return `Result{Changed, StartedOver}`; `Add`/`Remove` stay as `(bool, error)` wrappers so the ~41 existing call sites, `internal/github/watchsource_test.go` and `cmd/prv` need no change (RESEARCH Pattern 4).
- **`x/sys/unix` over `syscall` (Claude's discretion, D-08):** the module is already linked into the binary; only the go.mod line moves.
- **Linux not run here (RESEARCH A7):** flock polling and link(2) are verified on darwin/arm64 and cross-compiled for Linux; the man pages are cited in RESEARCH. If a Linux host is available, run `go test ./internal/watchlist -race -count=1` there and record it in the SUMMARY.
- **No legacy size check (RESEARCH optional hardening, skipped):** a truncated `watchlist.json.corrupt-HASH8` left by the pre-Phase-5 code before this fix still counts as "already backed up". New code can no longer create one.
- **O_CLOEXEC (RESEARCH A3):** Go opens every file close-on-exec; the lock file is also closed before AddRef/RemoveRef return.
- Spec-less probe fallback: skipped visibly (the phase has no requirement IDs to probe); no probe predicates are generated.
