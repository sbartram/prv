# Phase 02 Plan 01: Tracer — prv refreshes itself on the config interval, `r` refreshes at once, and a failed refresh never hides or fakes the data

## Phase Goal

**As a** developer who keeps prv open in a terminal pane all day, **I want to** have it refresh itself, stay inside the API rate limit, narrow the list and jump to a PR on github.com, **so that** I can trust that what I see is current without opening a browser.

(Derived from the ROADMAP Phase 2 Goal line, which is not written in user-story form; see the planner's return note.)

<objective>
Prove the refresh architecture end-to-end first, then make it trustworthy.

- Task 1 (tracer): `refresh_interval` in `config.toml` → `cmd/prv` → `ui.Options.Interval` → one generation-stamped tick chain → `Fetcher.Fetch` (the real github client in the end-to-end test) → header `updated HH:MM:SS`.
- Task 2: `r` refreshes from any screen, merges with a running refresh, a failed refresh keeps the rows, the first-fetch failure retries on its own, a spinner shows while a refresh runs, and a real `tea.Program` proves under `-race` that refreshes never overlap.
- Task 3: the header and footer tell the truth on any width: the D-07 failure marker with a short reason, D-09 "retrying at", integrity notes before key hints (WR-03), the WR-02 empty screen, and key hints from one keymap.

Purpose: success criterion 1 (interval from config, `r`, last-update time, defaults without a config file) and the "keeps last data" and "no overlapping refreshes" parts of success criterion 2. Decisions D-05, D-07, D-09, D-14 (refresh_interval), D-17 (keymap source). Roadmap pitfalls: single-flight, one tick chain, generation counter, coalesced `r`, panic-safe Cmds, cancel on quit.
Output: `internal/config`, `internal/ui/refresh.go`, `internal/ui/keys.go`, the refresh state machine in `internal/ui/model.go`, the header/footer composer in `internal/ui/view.go`, `Error.Short()`.
</objective>
