# Phase 04 Plan 06: Remove a PR I added — d, then y

## Phase Goal

**As a** prv user who watches pull requests from a terminal pane, **I want to** add any github.com PR by pasting its link, remove the ones I added, and keep them across restarts, **so that** at a glance I can see which of my watched PRs are approved, blocked, or failing CI (PRs I do not own included), and a PR that cannot be loaded says why instead of vanishing.

(The capability comes from the ROADMAP Phase 4 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Let the user take a PR off the watch list, and only the PRs they added.

- Task 1: the removal path end to end: `d` → confirm line → `y` → `Watchlist.Remove(row.Watched)` in a Cmd → the row leaves the list; proven through the real client, store and model.
- Task 2: every other case: the locked rule that any key but `y` cancels (q included) and only ctrl+c quits; unpin of a row that is also authored or assigned (D-07); the note for a discovery-only row and the detail view (D-08); unavailable rows (D-11); an entry already gone; a failed write; the last row; a refresh that raced the removal.

Purpose: ROADMAP success criterion 3 ("only manually added PRs can be removed"). Decisions D-06, D-07, D-08 (the d half), D-11 (d on unavailable rows) and the user decision recorded during plan-phase on 2026-10-12 (RESEARCH Open Question 2 / Pitfall 11). Edge-probe item WATCH-06 idempotency, ui side (the store side is plan 04-04).
Output: `internal/ui/remove.go`, `internal/ui/remove_test.go`, key bindings, the confirm line, `TestRemoveEndToEnd`.
</objective>
