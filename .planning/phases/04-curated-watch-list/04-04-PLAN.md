# Phase 04 Plan 04: The saved list survives anything — restarts, two panes, hand edits and a broken file

## Phase Goal

**As a** prv user who watches pull requests from a terminal pane, **I want to** add any github.com PR by pasting its link, remove the ones I added, and keep them across restarts, **so that** at a glance I can see which of my watched PRs are approved, blocked, or failing CI (PRs I do not own included), and a PR that cannot be loaded says why instead of vanishing.

(The capability comes from the ROADMAP Phase 4 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Harden the store from plan 04-01 and prove the live sync between panes.

- Task 1: `internal/watchlist` handles every bad file without losing data: a hash-named backup for a corrupt, unknown-version or oversized file; validation that skips but keeps bad entries; a cap of 500; an atomic write that never leaves a temp file; Add and Remove that refuse to write over a file they cannot read; two stores on one path.
- Task 2: the fetch path and the binary: each refresh re-reads the file (another pane's add and remove show up), a broken file mid-session keeps the last list, a saved PR that discovery already found costs no request, and startup problems show once as warnings.

Purpose: ROADMAP success criterion 3 ("manually added PRs reappear after the user quits and restarts prv") and the roadmap pitfalls "versioned JSON, atomic write, tolerant load, backup of a corrupt file, never remove manual entries automatically". Decisions D-16 and the carried-forward store rules; D-15-style warnings (Claude's discretion). Edge-probe items WATCH-06 idempotency and concurrency (the store side of removal).
Output: the robust store, `watchlist_test.go`, `watchsource_test.go`, `watchWarnings` in `cmd/prv`.

This plan runs in parallel with 04-02 (github lookup and its tests) and 04-03 (ui). It owns `internal/github/client.go` in this wave; its github test file uses only helpers prefixed `ws` and the existing rtFunc, jsonResp, fixtureBytes, opName and failingNoneBody, so it shares no new name with plan 04-02 (which adds `fixedRefs` and the fixtureTransport Lookup route).
</objective>
