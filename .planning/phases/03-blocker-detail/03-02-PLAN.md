# Phase 03 Plan 02: The list stays readable in a narrow pane and after a resize

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

<objective>
- Task 1: a pure `layoutColumns` replaces the fixed column math. As the pane narrows, TITLE shrinks, then AUTHOR, STATE and TITLE drop in the D-13 order, then the CI name and the PR ref shorten; PR, REVIEW and CI always stay. Goldens gain 60x15.
- Task 2: below 40 cells the list switches to compact rows (`> web#7 ✗✗`) with a "widen for columns" hint on the column-header line (D-14); tiny heights keep the selected row; a property test proves no width or height breaks the screen.

Purpose: success criterion 4 for the list ("in a narrow pane, and after a terminal resize, the list ... drop[s] or truncate[s] columns and stay[s] readable and navigable"). The column table is data-driven so plan 03-03 slots REVIEWERS and MERGE into the same drop order. The detail view gets the same treatment in plans 03-04 and 03-05.
Output: `layoutColumns`, `sizes`, `layout`, `dropSteps`, compact rendering, `Review.Glyph()`, `CI.Glyph()`, `internal/ui/layout_test.go`, 60x15 goldens and a compact golden.
</objective>
