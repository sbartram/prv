# Phase 03 Plan 02: Failing-check names stay right on messy real data and in a narrow CI cell

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

<objective>
- Task 1: the failing name stays right on real-world data: superseded re-runs, truncated pages, partial GraphQL errors, many failing PRs, rate limits, server errors and cancellation (D-01, D-02 revised, D-03, the "never guess a name" discretion item, the Phase 2 rate-limit rules).
- Task 2: a long, CJK or emoji check name is shortened inside the 24-cell CI cell while " (cancelled)" and " +N" stay.

Purpose: success criterion 2 holds on the data users actually have, not only on the tracer fixture. Roadmap pitfalls: re-runs are not double-counted; the badge never comes from a truncated page; display-width helpers.
Output: `internal/github/checks_test.go`, three step-2 fixtures, the suffix-preserving cut in `ciCell`, `internal/ui/cells_test.go`.
</objective>
