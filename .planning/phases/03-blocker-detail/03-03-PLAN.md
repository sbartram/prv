# Phase 03 Plan 03: Each row shows who is reviewing and whether the PR can merge

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

<objective>
- Task 1: a MERGE column (mergeable / blocked / behind / conflicts / –) from `mergeStateStatus` and `mergeable`, decided from state and draft first (D-07 as revised, RESEARCH F4/F5).
- Task 2: a REVIEWERS column (`✗bob …carol ✓alice`) from `latestOpinionatedReviews` plus `reviewRequests`, with pending-wins, hidden teams and `+N` (D-06, RESEARCH F6/F7); both columns join the D-13 drop order.

Purpose: success criterion 1 ("each row shows which reviewers approved, which requested changes, and which are still pending, plus merge-readiness"). Roadmap pitfalls: DISMISSED, a COMMENTED review that hides an approval, team and bot reviewers through union fragments with nil guards, re-requests.
Output: `domain.Merge`, `DeriveMerge`, `domain/reviewers.go`, extended discovery query and mapper, `blockers.json`, `reviewersCell`, MERGE and REVIEWERS columns, help legend lines, regenerated goldens.
</objective>
