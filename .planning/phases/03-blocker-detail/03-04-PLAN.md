# Phase 03 Plan 04: Merge readiness and reviewers reach every PR from GitHub

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

<objective>
- Task 1: every refresh gives each PR a merge-readiness value (mergeable / blocked / behind / conflicts / – / blank) from `mergeStateStatus` and `mergeable`, decided from state and draft first (D-07 as revised, RESEARCH F4/F5).
- Task 2: every refresh gives each PR its reviewers from `latestOpinionatedReviews` plus `reviewRequests`, with pending-wins, hidden teams and bots (D-06, RESEARCH F6/F7).

Purpose: the data half of success criterion 1 ("each row shows which reviewers approved, which requested changes, and which are still pending, plus merge-readiness"). Plan 03-05 draws the MERGE and REVIEWERS columns from these fields; plan 03-06 reuses the reviewer wire types and MergeReviewers for the detail view. Roadmap pitfalls: DISMISSED, a COMMENTED review that hides an approval, team and bot reviewers through union fragments with nil guards, re-requests.
Output: `domain.Merge`, `DeriveMerge`, `domain/reviewers.go`, extended discovery query and mapper, `blockers.json`, hostile reviewer data in `status.json`.
</objective>
