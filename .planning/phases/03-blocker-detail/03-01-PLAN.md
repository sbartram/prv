# Phase 03 Plan 01: Tracer — a failing PR's row names the check that is failing

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

(The capability comes from the ROADMAP Phase 3 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Prove the D-01 two-step fetch end to end first, then make it right on messy real data.

- Task 1 (tracer): discovery → FailingChecks `nodes(ids:)` query for the failing PRs → `domain.ClassifyCheck` / `LatestChecks` / `SummarizeFailing` → `PR.Failing` → CI cell `✗ lint +2`, proven by an end-to-end test through the real `github.Client` and `ui.Model`.
- Task 2: names stay right on re-runs, cancelled-only PRs, truncated pages, partial errors, many failing PRs and hostile names; cost and errors follow the Phase 2 rules.

Purpose: success criterion 2 ("the row for a PR with failing CI names one of its failing checks"). Decisions D-01, D-02 (revised), D-03, D-04 and the "never guess a name" discretion item. Roadmap pitfalls: the list badge always comes from the rollup state, re-runs are not double-counted.
Output: `internal/domain/checks.go`, `internal/github/checks.go`, `internal/ui/cells.go`, routed fixture transports, step-2 fixtures and tests.
</objective>
