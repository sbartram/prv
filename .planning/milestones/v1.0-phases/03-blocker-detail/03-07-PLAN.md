# Phase 03 Plan 07: Selecting a PR opens a detail view of every check and every reviewer

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

<objective>
- Task 1: enter opens a full-screen detail of the selected PR from one FetchDetail call: checks failing first, reviewers with their state, j/k scrolling, esc back to the same PR, o/r/q/? as in D-09.
- Task 2: big matrices stay readable: passing checks fold into "… +N more passing", e expands; a partial read keeps its de-duplicated counts and says how many runs were read; goldens and the help legend.

Purpose: success criterion 3 ("selecting a PR opens a detail view that lists every check/job with its status, failing first, and every reviewer with their review state; returning to the list keeps the same PR selected"). Refresh-while-open (D-11) and the PR leaving the list (D-12) are plan 03-08. The data comes from plan 03-06 (`FetchDetail`, `domain.Detail`).
Output: `internal/ui/detail.go`, keys enter/esc/e, `DetailShortHelp`, `DetailFetcher`, detail goldens.
</objective>
