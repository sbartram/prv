# Phase 03 Plan 08: The open detail view stays current and honest, and fits any pane

## Phase Goal

**As a** prv user watching my pull requests, **I want to** see without leaving the terminal who and what is holding each PR up (which reviewers, which failing check, and whether it can merge), **so that** at a glance I can tell which watched PRs are approved, blocked, or failing CI.

<objective>
- Task 1: while the detail is open it refreshes with each successful refresh (D-11), never applies a stale result, respects the rate-limit pause, keeps the last data on a failure, and stays open with a "no longer in list" note when its PR leaves the list (D-12); esc always lands on the right PR (DETL-03).
- Task 2: the detail lays itself out at any width (compact below 40 cells), survives resizes with a valid scroll position, and has goldens for every detail state at 60x15, 80x24, 120x40 and 0x0.

Purpose: success criteria 3 ("returning to the list keeps the same PR selected, also when a refresh happened while the detail view was open") and 4 (the detail view in a narrow pane and after a resize). Roadmap pitfall: the detail view handles a PR that leaves the list during a refresh.
Output: `refreshDetail`, gone/error/pause lines, narrow detail lines, the end-to-end detail test, detail goldens for the remaining states.
</objective>
