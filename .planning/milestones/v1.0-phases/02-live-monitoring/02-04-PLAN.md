# Phase 02 Plan 04: The header and footer tell the truth on any width — failure marker with a short reason, "retrying at", integrity notes before key hints, honest empty screen

## Phase Goal

**As a** developer who keeps prv open in a terminal pane all day, **I want to** have it refresh itself, stay inside the API rate limit, narrow the list and jump to a PR on github.com, **so that** I can trust that what I see is current without opening a browser.

<objective>
- Task 1: the header tells the truth on any width: a failed refresh shows the D-07 marker with a short reason and the time of the data on screen, the error panel says when it retries (D-09), and a priority composer keeps the marker when the pane is narrow (Pitfall 10).
- Task 2: the footer tells the truth on any width: integrity notes come before key hints (WR-03), key hints come from one keymap (D-17), and the empty screen no longer claims "No open PRs" over a partial load (WR-02).

Purpose: the "error indicator" part of success criterion 2 and the honest-screen fixes WR-02 and WR-03 from the Phase 1 review. Decisions D-07, D-09, D-17 (keymap source for the footer).
Output: `(*github.Error).Short()`, `fit()` and `footer()` in `internal/ui/view.go`, `warnStyle` and `helpStyles()` in `internal/ui/styles.go`, the `help` model field.
</objective>
