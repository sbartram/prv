# Phase 02 Plan 05: The footer shows how much API budget is left, and the header warns in yellow when it drops below 20%

## Phase Goal

**As a** developer who keeps prv open in a terminal pane all day, **I want to** have it refresh itself, stay inside the API rate limit, narrow the list and jump to a PR on github.com, **so that** I can trust that what I see is current without opening a browser.

<objective>
- Task 1: every fetch carries the full rate-limit picture: the query gains `limit`, and `domain.RateLimit` gains `Limit`.
- Task 2: the remaining API budget is visible as a faint `api N` at the right end of the footer, and it turns into a yellow header warning with the reset time below 20% (D-06).

Purpose: the "status bar shows the remaining API rate limit" part of success criterion 2. Decision D-06. Roadmap pitfall: every query includes rateLimit (with `limit` added for D-06). Plan 02-06 uses the same data for the automatic backoff.
Output: `RateLimit.Limit`, the `limit` selection in the discovery query, the `api N` footer segment, the prio-6 header warning.
</objective>

## Decision notes

- D-06 narrowing (made explicit, per checker INFO): "always shows" cannot hold before the first successful response, because no rate-limit data exists yet. The api segment therefore appears from the first successful fetch on and keeps the last known value through failed refreshes. A made-up "api ?" is not shown, because it would read like a value.
- The 20% threshold is a display rule only. The pause rules (reserve, pacing) are plan 02-06.
