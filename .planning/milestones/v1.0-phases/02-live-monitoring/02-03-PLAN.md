# Phase 02 Plan 03: The PRs that need attention come first, and the order holds still between refreshes

## Phase Goal

**As a** developer who keeps prv open in a terminal pane all day, **I want to** have it refresh itself, stay inside the API rate limit, narrow the list and jump to a PR on github.com, **so that** I can trust that what I see is current without opening a browser.

<objective>
- Task 1: `domain.Bucket` puts every PR in its D-01 attention bucket, with open drafts in bucket 6 (D-04) and merged or closed drafts with their lifecycle state (D-04 as clarified by the user on 2026-10-12).
- Task 2: rows come back from GitHub in attention order — failing CI and changes requested first — with tie-break keys that polling does not change (D-02). The query gains `createdAt`.

Purpose: the sort half of success criterion 3 ("sorted by need for attention, the order does not shuffle"); plan 02-02 delivers the "selection stays selected" half. Roadmap pitfall: stable sort on a key polling does not change.
Output: `domain.Bucket`, new `domain.Sort`, `PR.CreatedAt`, `createdAt` in the query.
</objective>

## Decision trace

- D-04 as clarified by the user on 2026-10-12 (CONTEXT.md, commit ea6b159): "draft always sorts into bucket 6" applies to OPEN drafts. Lifecycle state is checked first, so a merged or closed draft sorts with merged or closed PRs. Task 1 implements this by switching on pr.State before reading pr.IsDraft, and TestBucket pins both a merged draft (7) and a closed draft (8). This is a user decision, not a planner reading.
- RESEARCH A3: approved with no checks or unknown CI is bucket 5 (Claude's discretion in CONTEXT), so "ready to merge" never rests on "no checks".
- Unknown lifecycle state sorts after closed ("closed (then unknown state)" in D-01); Bucket returns 9 for it.
