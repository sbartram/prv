# Phase 02 Plan 07: Real GitHub rate-limit responses are recognised — the HTTP-200 primary limit and the 403/429 secondary limit — and pause prv end to end

## Phase Goal

**As a** developer who keeps prv open in a terminal pane all day, **I want to** have it refresh itself, stay inside the API rate limit, narrow the list and jump to a PR on github.com, **so that** I can trust that what I see is current without opening a browser.

<objective>
- Task 1: a header-capturing transport and `KindRateLimited` with `Backoff()` recognise the HTTP-200 primary limit (headers plus `RATE_LIMITED`) and the 403/429 secondary limit, so the plan 02-06 policy pauses on real responses.
- Task 2: a rate limit on a later discovery page is an error, not a truncated list; an end-to-end test through the real client shows the failure marker, the paused marker, the refused `r` and the budget.

Purpose: completes the rate-limit half of success criterion 2 on real GitHub responses. Decisions D-06, D-07, D-08 end to end. Roadmap pitfall: backoff honours retry-after, then resetAt.
Output: `internal/github/ratelimit.go`, rate-limit classification in `internal/github/errors.go`, capture wiring and the later-page rule in `internal/github/client.go`, `TestRateLimitedEndToEnd`.
</objective>

RoundTrip(r *http.Request) (*http.Response, error) calls t.base.RoundTrip(r), then under the mutex sets t.last from resp.Header.Get("Retry-After"), Get("X-RateLimit-Remaining") and Get("X-RateLimit-Reset") when resp is non-nil, or to the zero value when it is nil; it reads no request header at all and no other response header (the token travels in a request header and must never be read here; AUTH-03).
