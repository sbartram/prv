# Phase 04 Plan 02: Every paste and every saved PR that GitHub refuses is explained in its own words

## Phase Goal

**As a** prv user who watches pull requests from a terminal pane, **I want to** add any github.com PR by pasting its link, remove the ones I added, and keep them across restarts, **so that** at a glance I can see which of my watched PRs are approved, blocked, or failing CI (PRs I do not own included), and a PR that cannot be loaded says why instead of vanishing.

(The capability comes from the ROADMAP Phase 4 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Finish the reference parser and the GitHub-side reason for every PR that does not load. Both are visible at once through the add prompt from plan 04-01, which shows the parser's reason and the Lookup reason inline.

- Task 1: an exhaustive table of accepted and rejected inputs (D-04) drives `domain.ParseRef` to its final form; `domain.SSORequired` and the final `LoadFailed` wording (D-10).
- Task 2: `lookupRefs` attributes every GraphQL error to its alias by `errors[].path[0]` and maps it to the three D-10 reasons, keeps nested errors as warnings, and is covered by fixture tests (live NOT_FOUND shapes from the spike, constructed SAML shapes, chunking, request-level failures, cleaning, and the Fetch-level D-12 rule).

Purpose: ROADMAP success criterion 2 ("pasting a malformed reference, a PR that does not exist, or a PR the token cannot access shows an inline error that explains why") and the GitHub half of criterion 4 / LIST-09. Decisions D-04, D-10, D-12 (row 1). RESEARCH Pattern 2, Pattern 3, Pitfall 3, assumption A1.
Output: `internal/domain/ref_test.go`, attribution in `internal/github/lookup.go`, `lookup_test.go`, `lookup_mixed.json`, a Lookup route in the test transport.

This plan runs in parallel with 04-03 (ui) and 04-04 (store, github watch-source tests). It does not change `lookupRefs`' signature or `client.go`.
