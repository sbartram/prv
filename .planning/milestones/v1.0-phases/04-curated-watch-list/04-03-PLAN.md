# Phase 04 Plan 03: The add prompt is forgiving — typos are explained, duplicates jump to the row, and a refresh can never undo an add

## Phase Goal

**As a** prv user who watches pull requests from a terminal pane, **I want to** add any github.com PR by pasting its link, remove the ones I added, and keep them across restarts, **so that** at a glance I can see which of my watched PRs are approved, blocked, or failing CI (PRs I do not own included), and a PR that cannot be loaded says why instead of vanishing.

(The capability comes from the ROADMAP Phase 4 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Make the add prompt from plan 04-01 behave right in every situation a user meets.

- Task 1: duplicates (D-03: by key before the request, by node ID after it, hidden by filters), every save outcome (saved elsewhere, hidden by filters, from the empty screen), and the stale-refresh rule (RESEARCH Pitfall 1: an epoch on every fetch).
- Task 2: the input itself: where `a` works, typing and paste cleaning, every inline error with the text kept, esc and late results, the rate-limit pause, and a prompt line that fits any pane.

Purpose: ROADMAP success criteria 1 ("pasting a PR that is already listed ... does not create a second row") and 2 ("shows an inline error that explains why, and nothing is saved"). Decisions D-01, D-02, D-03, D-08 (the `a` half). RESEARCH Pitfalls 1, 5, 6, 7, Pattern 6, Pattern 7. Open Question 2 is not in this plan: the confirm prompt is plan 04-06.
Output: changes in `internal/ui/add.go`, `model.go`, `refresh.go` and the new `internal/ui/add_test.go` with fakes reused by plans 04-05..04-07.

This plan runs in parallel with 04-02 and 04-04 and touches no file they touch. Its tests build Unavail values as literals (domain.Unavail{Kind: domain.UnavailSSO, ...}) and never call domain.SSORequired, which plan 04-02 adds in the same wave.
</objective>
