# Phase 04 Plan 07: Everything is discoverable and readable — the unavailable detail, the hints, the help legend and the goldens

## Phase Goal

**As a** prv user who watches pull requests from a terminal pane, **I want to** add any github.com PR by pasting its link, remove the ones I added, and keep them across restarts, **so that** at a glance I can see which of my watched PRs are approved, blocked, or failing CI (PRs I do not own included), and a PR that cannot be loaded says why instead of vanishing.

(The capability comes from the ROADMAP Phase 4 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Finish what the user sees: why a saved PR is unavailable, how to find the new keys, and pinned snapshots of every new screen.

- Task 1: `enter` on an unavailable row opens a reason-only detail (D-11): the reason, the SSO hint, `o` to the PR's github.com page, no Detail request; a PR that comes back starts its normal detail fetch.
- Task 2: the footer hints `a add` and `d remove` (D-15), the empty-screen hint, the `?` overlay keys and legend (D-05, D-09, D-17), and golden files for every new state plus the regenerated existing ones.

Purpose: ROADMAP success criterion 4 ("shows as an unavailable row with the reason") reaches its last detail: the full reason and the SSO hint (D-10, D-11). D-15 makes adding and removing discoverable. The Phase 3 golden rule (0x0, 60x15, 80x24, 120x40) covers every screen this phase adds, as CONTEXT lists them.
Output: `detail.go`, `keys.go`, `view.go` footer and empty text, `help.go` legend, tests, and the generated golden files under `internal/ui/testdata/` (the exact set is pinned by Task 2's acceptance criteria).
