# Phase 04 Plan 01: Tracer — paste a PR link, it is saved, and it comes back after a restart

## Phase Goal

**As a** prv user who watches pull requests from a terminal pane, **I want to** add any github.com PR by pasting its link, remove the ones I added, and keep them across restarts, **so that** at a glance I can see which of my watched PRs are approved, blocked, or failing CI (PRs I do not own included), and a PR that cannot be loaded says why instead of vanishing.

(The capability comes from the ROADMAP Phase 4 Goal line and the outcome from the PROJECT.md Core Value. The ROADMAP Goal line is not written in user-story form; see the planner's return note.)

<objective>
Prove the whole watch-list path end to end first, then make it survive a restart.

- Task 1 (tracer): `a` → add prompt → paste a PR URL → `enter` → `domain.ParseRef` → one aliased `Lookup` GraphQL request (variables only) → `watchlist.Store.Add` (atomic write) → the PR appears in the list with full status, the `+` marker and the cursor on it. Proven by an end-to-end test through the real `github.Client`, a real `watchlist.Store` in a temp dir and the real `ui.Model`.
- Task 2: every refresh reads the saved list (inside the fetch Cmd), skips saved PRs that discovery already returned, looks up the rest, and merges both sources by key and by node ID; `cmd/prv` wires the store into the binary. Proven by a restart test: a second client and model on the same file list the saved PR again.

Detector: `assumption-delta scan 04` fired `pluralization` on "second row". The signal is real: the list had one source (discovery: authored or assigned) and now has a second (the saved watch list).

- Primary noun: the **watched PR**. Its identity is the GitHub node ID when it loaded, and the saved key (`Ref.Key()`: owner/repo lowercased, number) when it did not load or when it is matched against the file.
- Decision: **promote**. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyboard / paste → prv | Pasted text is untrusted: it can hold escape sequences, newlines and very long strings |
| prv → GitHub API | Owner, repo and number from the user travel to GraphQL |
| GitHub API → prv | nameWithOwner, titles, author logins and error messages are remote strings drawn on screen |
| prv ↔ local file | watchlist.json is written by prv and may be edited by hand or by another prv instance |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering (query injection) | buildLookup / lookupVars | high | mitigate | Only the integer alias index is formatted into the document; owner, repo and number travel only as $oN/$nN/$pN variables; ParseRef admits only the owner and repo character classes and 1..2147483647; TestAddEndToEnd asserts the query text holds none of the pasted values |
| T-04-02 | Tampering / Spoofing (terminal escapes) | addKey / addPaste / addLine | high | mitigate | Every typed or pasted string passes domain.Clean (CR and LF become spaces first) before it is stored or drawn; the buffer is capped at 256 runes |
| T-04-03 | Tampering / Spoofing (terminal escapes) | mapNode via lookupRefs | high | mitigate | Lookup reuses mapNode, which cleans every remote string with domain.Clean at the github seam (the discovery mapper, unchanged) |
| T-04-04 | Information disclosure | watchlist.json | low | mitigate | The file holds repo, number and added_at only (never the token or PR data); the directory is created 0700 and the file 0600 (CreateTemp) |
| T-04-05 | Tampering (data loss) | Store.Add / Store.Remove | medium | mitigate | read() errors stop the write; the write goes to a temp file in the same directory and is renamed over the file, so a crash leaves the old file intact; invalid hand-edited entries are kept untouched |
| T-04-SC | Tampering | Go module installs | high | mitigate | No new modules; `git diff --exit-code go.mod go.sum` |
